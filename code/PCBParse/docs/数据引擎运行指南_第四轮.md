# 数据引擎运行指南 · 第四轮（WSL Ubuntu，目录 /mnt/c/EDA）

## 这一轮改了什么
- **下载器修好了**：上一轮约 95% 的工程失败，原因有两个，都已修复：
  1. "empty sheets"（103 个）：新工程的原理图不直接返回，而是放在 CDN 上的一个文件里，内容用 AES-256-GCM 加密并经过 gzip 压缩。解密用的 key 和 iv 由接口随文档一起返回，编辑器自己也是这样解密的。我用调试数据验证过，解出来就是标准的原理图数据。
  2. "no schematic"（97 个）：新工程的文档列表里没有 docType 字段，旧代码把它们全部过滤掉了。
- **滚雪球发现**：加上 `--expand` 后，每个新发现的工程都会再作为种子继续扩展，不再只有 4 个种子。
- **数据集生成**：
  - 每个工程最多取 8 张图（`--per-project 8`），同一工程的多个版本之间去重更严格。上一轮 27 例里有 12 例来自同一个工程。
  - 打分改为每个案例单独起一个进程，单例内存不足只影响这一例，不会中断整批。
- **解析器**（公开 13 题仍为 97.88；27 个新案例从 82.3 提到 83.2；8 个专业版样例从 86.3 提到 86.5）：
  - 根据字形宽度区分 O 和 0（PA0、BOOT0），以及区分 IO 和 10。
  - 没有印型号的芯片，Name 不再取附近的网络标签。
  - 去掉手画的分区框线（例如 "TYPEC接口"、"MUX" 外面的红色方框）。以前这些框会把整页粘成一个元件。
  - 大于 900 万像素的图不再放大 2 倍，避免内存不足。

## 第 2 步：通宵批量下载（目标 3000 个工程）
```bash
cd /mnt/c/EDA/PCBParse
nohup python tools/oshw_fetch.py --out /mnt/c/EDA/raw --list /mnt/c/EDA/retry.txt \
    --seed d54b0d8e884945fb8d875979510b5211 --seed dff8db20c1ec4e4c94a0117b038f4699 \
    --seed 2685b31277e94ef9b2fced6df44d9cf4 --seed 44c23560bfb145f885bca4c886157c01 \
    --expand --max 3000 --delay 1.5 --cookie /mnt/c/EDA/cookie.txt \
    > /mnt/c/EDA/fetch_v5.log 2>&1 &
```
- 每个工程约 10–20 秒，一夜（8–10 小时）大约 2000–3000 个。中断后重新运行同一条命令即可续传，已成功的工程会自动跳过。
- 查看进度：`tail -5 /mnt/c/EDA/fetch_v5.log`；已下载数：`ls /mnt/c/EDA/raw/bundles | wc -l`。
- 统计成功率（**正常应远高于上一轮的 10%**）：
```bash
grep -o " ok \| empty sheets\| no schematic\| documents/lists failed" /mnt/c/EDA/fetch_v5.log | sort | uniq -c
```
- 请求间隔保持 1.5 秒，不要调低。

## 第 3 步：第二天早上生成数据集并打分
```bash

rm -rf /mnt/c/EDA/dataset
nohup python tools/build_dataset.py --raw /mnt/c/EDA/raw --out /mnt/c/EDA/dataset \
```
