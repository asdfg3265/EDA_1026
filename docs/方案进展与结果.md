## v15（2026-10-25，PCBParse_v18 / submission_v15）：逐例排查剩余失分
- **评测标注**：本轮起开发集、留出集改用标注生成器修正后的新版标注（ds80g9 / ds150g9），数字不能与前几版直接相减。同一标注下的对比（平台规则；括号内为 10-22 规则）：
  - 开发集 89.16（91.27）→ **90.14（92.27）**；
  - 留出集 88.10（90.11）→ **88.92（91.02）**；
  - 带图框开发集 **88.15（90.11）**，带图框留出集 **87.54（89.18）**；
  - 合成 Altium / KiCad 82.69 / 85.52（10-22 规则）。
- **公开题**：13 题输出与 v14 逐字节相同（99.38；10-22 规则 99.79）。submission_v15 按平台入口实跑，13 题输出与本地一致，单进程 60 s。
- **文字颜色**：嘉立创的位号和网络名是藏青，型号和取值是亮蓝。
  - 亮蓝文字不当位号，藏青文字不当取值；
  - 离开导线的藏青单词给没有位号的器件补名；
  - 粘在一起的两行文字按颜色分界切开。
- **电源与端口**：
  - 形状识别出的电源可以取“3V3”这类电压名，单例 +10 分；
  - 一列紧贴的端口按整列一次性分配标签；
  - 电源名纠错：YDD_3V3、ZVCC25 改回本图常见写法；BGND 这类带前缀的地名保留。
- **器件结构**：
  - 边贴边叠放的电阻按单元格拆开；
  - LED 的实心光箭头不再被认成地符号，分开画的箭头并入二极管（电阻和锯齿电阻除外）；
  - 隐藏位号不推给贴着已命名小件的本体。
- **类型与引脚**：
  - 三极管必须有一个单位长的斜线；
  - 标注规则没有列出的前缀按标注规则判型，并在合并之后才判型；
  - 未命名或 PC817A-D 光耦的引脚名取 AN/CAT/EM/COL（PC817X2CSP9F 等仍用数字）；
  - IC 引脚名里丢失的逗号会补回。
- **位号**：
  - 修正 R5.、C-35、LD01、USBCT、UE（四字母前缀重解码、按数字得分纠回）；
  - KiCad 引脚号不当位号；
  - 常见管子型号压在导线上也取作 Name。
- **试过但改掉的**：
  - 判型放在合并之前：会打断 ZX1 等器件的合并；
  - 地符号旁有斜线就不切出：端口的斜边会误伤；
  - 光耦一律取 AN/CAT：PC817X2 的标注用数字；
  - 位号 'PR.1' 去点：标注里就带点。

## v14（2026-10-24）：图框、标题栏与功能框
- **起因**：10-23 答疑说最终评测可能出现图框和功能框。官方 200 个训练图中有 **107 张带图框和标题栏**（嘉立创 87 张，Altium、KiCad、Datasheet 也有），功能框（虚线/实线框，框内写“电源电路”等标题）也很常见；公开 13 题中两类都没有。v13 在带图框的官方嘉立创图上几乎每张都把整页图框认成一个元件（“A4”“V10”“P1” box，或把“V1.0”认成电源）：99 张中有 **91 个整页大框**。
- **新文件 `pcbparse/frame.py`**（解析前预处理）：
  - 图框：四边都有贯穿整页（≥60%）且能围成矩形的直线才算；与外框相距不超过页面 4% 的最内侧线为内框。擦边框线时保留交叉笔画；两框之间只擦不大于分区带的小块（编号、刻度）。
  - 标题栏：只找右下角；整块及左右两侧都要是行高不超过页高 12% 的表格并有竖线；顶部的单行文字格或空白格（KiCad 注释区）可向上并入。早期版本曾误把角落里画了电路的功能框当标题栏（p03 样例、训练 0185/0198），加了这些条件后不再出现。官方训练图 108 张检出结果逐张核对，没有擦掉电路。
  - 裁剪：去掉图框后按内容包围盒解析，坐标换算回原图（整页图 > 9 MP 时此前跳过小字放大，一例 73.4 → 84.9）。
  - 虚线/点划线：≥5 段、等距（间距与段长相当）、两侧 6 px 留白（相邻的另一条虚线除外）、端头整齐、笔直的短线段才擦。最初版本误擦电容极板、地符号横杠、竖排标签字母、线圈弧线，逐条加了限制。
- **其他**：无引脚的长直笔画（实线功能框的边）丢弃，不再抢位号；字高 ≥ 常规 1.8 倍的标题大字不作位号/型号（仍可作网络标签，曾有图纸用大字写端口标签）；OCR 对超宽“文字行”逐个识别并限宽（一张 4200×2800 整页图此前耗尽 8 GB 内存）。
- **误检**：公开 13、开发 99、留出 184、AD/KiCad 合成、10gt 共 322 张图上，图框和虚线检测均无误检。
- **结果**（平台规则；括号内 10-22 规则）：
  - 公开 13 题输出逐字节不变（99.3845）。开发集 87.80（89.78），仅 1 例输出变化、分数不变；留出集 86.39 → 86.41（88.29 → 88.32），5 例提高、无下降。
  - 带图框的开发集工程图 50 例：85.44 → **85.91**（87.14 → 87.69），同批不带框为 85.90（87.61）。
  - 带图框的留出集工程图 69 例：84.32 → **84.76**（85.84 → 86.34），16 例提高、2 例下降（最大 −3.4：图上“P沟道”这类说明文字被取作 MOS 管的 Name，v13 里它们碰巧被整页大框吞掉了）；另一张 4200×2800 的整页图 v13 内存耗尽，v14 为 74.7。
  - 官方嘉立创训练图 99 张：整页大框 91 → 10（剩下的是真的大芯片/接插件）。
  - 虚线功能框（按源文件线型渲染的 16 例）：92.95 → 92.96（我们渲染的虚线本来影响就小；官方 0082 那类细点划线影响更大）。
- **测试集**：`work/frame/build_framed.py`（同一工程页带 A4/A3 图框渲染，GT 不变）→ /tmp/claude-0/fr80（50）、fr150（70）；`work/frame/build_fb.py`（功能框：D 带源线型，N 去掉长框线，T 再去掉自由文字）→ fb_D/fb_N/fb_T（96）。渲染器 `easypro.render.DASHES` 可按源文件画虚线（默认关，已发布数据集不变）。

## 风格归一化（pcbparse/style.py，v12）
- **判别**：按“相对纸张的缺失向量方向”把像素分成颜色族；导线色 = 长直线段端点大量落在其他颜色墨迹上的那一族；嘉立创 = 绿导线 + 蓝/藏青文字 + 几乎没有青色文字。导线色在全部直线里占比不到 10% 时视为单色图，原样不动。嘉立创图原样返回（421 张核对）。
- **重绘**：每个像素按颜色和形状给角色（导线、连接点、符号笔画、文字），纸张网格和本体填充当纸。
- **验证**：合成 dsAD / dsKC（各 8 例）：嘉立创原版 89.5；v11 Altium 5.0、KiCad 4.6；v12 78.6 / 83.7；v13 79.5 / 84.2。

## 已核实的官方约定
- 同一位号多个部件记为 `<位号>_1, _2…`（从左到右）；网络端口类型按箭头方向；地符号名字隐藏时 value 为 'GND'，嘉立创空心三角形地为 AGND；运放引脚名 IN+/IN−/OUT/VCC/VEE；两脚器件 bbox 边在引脚端点内 1u；晶振照印出的频率输出。
- 地/电源：各分支分开写成不同的 net，评分时按名称合并（10-23 答疑）；v14 起按此输出。

## 已知未解决
- 非嘉立创：单色图（Altium 全藏青、LTspice）分不开导线与符号；KiCad 全局/层次标签会被当成芯片；Altium 反相圆圈/时钟楔形混进引脚号；低分辨率 Altium 图 OCR 不稳；KiCad 圆圈电源符号。
- 嘉立创：导线自定义颜色；叠画的反向并联 LED 箭头；导线穿过芯片外框时框内文字接错；被导线盖住一笔的字母。
- 图框：只处理四边完整的图框；残缺图框、标题栏不在右下角的图纸仍按普通图处理。器件旁的中文说明文字（“P沟道”）可能被取作 Name。
